# 会议待办质检器

> 第九届传智杯大学生数智创新与AI应用大赛 · 赛道：办公协同与组织效率
> 参赛形式：单人　｜　2026-11-25

## 在线演示

**<https://cbc080303.github.io/baiduai/>**

纯前端单文件页面，零外链、零依赖、不联网、不调用任何外部服务。打开后可以直接粘贴自己的会议转录，当场跑完一轮质检。

## 一句话定位

不是又一个会议纪要工具，而是**纪要生成之后的一道质检**——判断 AI 提取的待办准不准、缺不缺、能不能直接建进任务系统。

**核心结论：AI 从会议里提取的待办，一半以上不能直接用。**（第 1 组实测：11 条里可直接执行 6 条，54.5%）

页面内置两个校验通道，可信度不同，这是本作品的核心设计：

- **D 通道 · 核对原文依据**：字符串匹配，逐条验证待办的「原文依据」能否在转录里逐字找到。这一层能给硬结论——找到就是找到，找不到就是找不到，不依赖模型判断。
- **A 通道 · 查遗漏候选**：按人切片重扫，输出「表里没有、但某人被派了活」的候选。**只出候选，不下「遗漏」结论**，采纳与否由人裁决。

哪一层能判死、哪一层只能提示，页面上明确标注，不混着说。

## 页面怎么用

1. 打开线上地址（或本地双击 `index.html`）。
2. 在「试一试：把任意转录粘进来」里点 **载入示例转录**，或粘贴自己的会议转录。
3. 点 **核对原文依据（D）**：示例数据 25 条依据命中 24 条，只有生成版 #3 不匹配——这一条是故意留着的真实失配样本，不是 bug。
4. 点 **查遗漏候选（A）**：示例数据输出 4 条候选（赵敏／中、李思远／高、陈晨／高、王睿／高），与 Python 实现逐条一致。

A 通道靠转录里的「参会人：」行确定「谁被点名」。缺这一行时 A 通道不启动，D 通道不受影响。

## 三组语料验证了什么

| 组 | 语料 | 关键数字 | 说明什么 |
|---|---|---|---|
| 1 | 产品运营周会（本方构造，1,211 字） | 可直接执行 6/11（54.5%）→ 修正后 13/14 | 机制能跑通 |
| 2 | 国新办发布会实录（财政部官网，4,819 字） | D 8/9；A 候选 5 条**成立 0 条** | 规则会误报，且每条误报可解释 |
| 3 | VCSum 真实会议 ASR（ACL 2023，4,913 字） | 28 场抽样**内部分工例会 0 场**；三要素齐全 0/145 句 | 公开语料承载不了这项验证 |

三句话：

- **D 维度跨三组稳定在 90% 左右**——它是字符串匹配，不受语料类型影响。
- **A 维度成立率从 100% 掉到 0**——同一份脚本一行没改，差别只在语料里有没有「人名 + 指派」。
- **公开能拿到的中文会议语料，恰好是待办密度最低的那一类**。能验证的语料，恰好是拿不到的那一类。

第三组还暴露两个只在真实 ASR 语料上出现的问题：说话人标签是段落级（40 个标签覆盖 145 句，约 27% 粒度），会让按人切片整体失真；ASR 错字（「哑剧」应为「牙具」）会让逐字引用把噪声一起固化进证据链。

## 它在哪里不适用

写在前面，而不是等被问到：

- **适用于**：有人被点名、有事被分派的内部分工会议。
- **不适用于**：对外发布会、论坛、沙龙、学术分享——这些语料里没有「谁在什么时候做什么」。
- 第 2 组暴露的硬伤：责任主体是机构（「财政部／我们」）时，按人切片直接失明，某位发言人 12 句零候选。
- **数据性质**：第 1 组为构造语料，人物与企业均为虚构，用于演示方法；真实内部会议的召回率与字段准确率**尚未验证**。

## 两个口径，不要混用

- **可直接执行 13/14**：指字段齐全（动作／责任人／截止／依据四要件），不等于内容正确。
- **可直接建单 7/14**：指能直接建进任务系统。

这两个数定义不同，被问到时必须分开说，否则会被当成前后矛盾。
