会议待办质检工作台

粘贴转录与待办表，一次跑完输入体检、D 依据回查、A 遗漏候选、C 字段核查与风险分档。质检全在本机完成，不联网、不上传、不调模型；会议记录的语音识别是可选项——默认只走端上（音频不出本机），说明见记录卡。

电脑：把这个文件双击打开，或拖进 Chrome / Edge；断网也能用 手机：用系统浏览器打开 cbc080303.github.io/baiduai/workbench.html（长按整段可复制）；在微信里请先「在浏览器打开」，否则录音会被拦 录音：要麦克风授权 + https（线上或 localhost）；没有也能用文字录入 + 质检

0把材料丢进来就行

粘贴一段文字、拖入文件、或点「选择文件」（可多选）。系统会自己判断哪份是会议转录、哪份是待办表，放进下面两个框；两份齐了自动跑一遍。人工整理的稿子、录音转写稿、会议纪要都不用手工转换。

V视频会议 · 字幕与录像

会议录像导出的字幕（.vtt / .srt）拖进来就直接变成可质检的转录——时间码与说话人都保留，实时字幕那种越滚越长的重复行会自动去重。录像（.mp4 / .mov / .webm）只能读时长、分辨率与有无音轨——本页的语音识别只对麦克风实时说话，不处理已上传的录像文件，会给转文字的两条路，不假装能出纪要。


  


  

    
R会议记录 · 边录边记 可选

    
开会时点「开始录音」，随手记要点；也可点「语音识别」边说边出文字，一句话说完自动落一段，点「送入质检并运行」直接进下面的「会议转录」跑一遍。识别只出文字、不区分说话人——换人时点一下名字，之后的话就记到他名下；换人前还没到停顿的半句会先按原来的说话人落下，不会记到新人名下（浏览器端没有声纹分离，全自动区分要靠会议平台转写）。识别可以和录音同时开（两路共用一支麦克风，个别设备会抢不到，报 audio-capture 时只留一种）；不录音也有会话时间码，每行照顺序递增。优先走端上识别（音频不出本机）；但内置浏览器 / Electron 壳实测会让整页崩，这种环境本页自动改走浏览器默认方式（音频会发给浏览器厂商）并在状态行说明，要端上请用 Chrome / Edge 打开。记录有自动草稿：整页崩了或误关，重开本页会自动找回最近一次没保存的内容。

1会议转录

    
自动分拣会填这里；也可以自己粘。人工稿写 姓名：内容，录音转写稿带时间码和「听不清」也没关系，首行 参会人：张三、李四 缺了会从说话人标签反推。

    
只有「会议纪要正文」不行——那是概括过的文字，依据必然大面积不匹配。粘进来时体检会明确告诉你这一点，不会假装跑出 0 分。

    
    

      
      
      
      
    

  


  

    
2待办表

    
CSV / TSV / Markdown 表格都能识别。列名认 编号,任务,负责人,截止时间,约束,原文依据；缺「编号」自动补序号。

    
「原文依据」这一列不能省：没有它就无法做依据回查，工具会明确标成「不可检」而不是「全部不匹配」。

  口径：D 为字符串匹配（硬结论，默认去空白后比对）；A 只出候选、采纳权在你；C 区分「原文无线索」与「有线索未填」；风险分档按缺负责人 / 缺截止 / 责任共担 / 软要求 + 依据不可追溯加权，与 org_view.py 同向。

  三态：依据「不可检」（缺列或空串）不计入命中率分母，也不按「不可追溯」扣风险分——无法检查不等于检查失败。

  不做：B（误提）的语义裁决、语义级判断、录音转写、纪要撰写。附加的「软要求候选」只是规则召回，不是结论。

  边界：不带参会人名单时 A 通道不可用；同句两人时人物归属可能标成句内先出现者，候选必须人工改判。
